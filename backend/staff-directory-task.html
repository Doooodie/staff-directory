REST API — CRUD endpoints
Employees · Departments · Roles · search · pagination
0 / 0▾
Business scenario

An HR manager maintains a company directory. Each Employee belongs to one Department and has one Role. Employees are never hard-deleted — only deactivated (isActive = false).

Department: name, description.  ·  Role: title, level (junior / mid / senior).

✓
GET /employees — paginated list with search and department filter
Query: ?search=John&departmentId=uuid&page=1&limit=20. Response: { data, total, page, limit }
must
✓
GET /employees/:id · POST · PATCH /:id · DELETE /:id
DELETE = soft delete only — set isActive = false, do NOT remove the row
must
✓
Full CRUD for /departments and /roles
GET /departments should include the count of active employees per department
must
✓
DTO classes with class-validator on every endpoint
@IsEmail · @IsNotEmpty · @Min/@Max (salary) · @IsDateString (hireDate) · @IsUUID (relation IDs)
must
✓
Correct HTTP status codes on all responses
201 on create · 404 not found · 409 email taken · 400 validation error
must
✓
Global ExceptionFilter with a consistent JSON error shape
{ statusCode, message, error, timestamp } — no raw NestJS stack traces exposed
nice
✓
GET /employees/stats — total, active count, avg salary grouped by department
nice

Authentication — JWT
Register · login · guard all routes
0 / 0▾
Goal

Every endpoint except /auth/* requires a valid JWT. Unauthenticated requests return 401. A request with a valid token proceeds normally.

✓
POST /auth/register — hash password with bcrypt, return the user (without the password field)
must
✓
POST /auth/login — verify credentials, return a signed JWT access token
must
✓
Apply JwtAuthGuard globally; whitelist /auth/* with a @Public() custom decorator
must
✓
Passport JwtStrategy — validates the token and attaches req.user to the request
must
✓
Role-based guard: ADMIN can write, regular users can only read
